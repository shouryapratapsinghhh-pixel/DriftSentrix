# Assumptions and known deviations

Honest record of assumptions made, and places this build diverged from the
original phased spec (`AGENTS.md`), with the reasoning for each.

## Open TODOs

- **NASA SMAP/MSL `anomaly_sequences` inclusivity** (`data/loaders.py:load_nasa`):
  currently assumed **inclusive** `[start, end]` (both endpoints marked
  anomalous). Not yet verified against the real dataset in this environment
  — `scripts/inspect_labels.py` (which would plot labels against real data to
  confirm this) was never built, since Phase 0 started from an empty repo
  with no real dataset present to inspect. **Action before trusting real
  SMAP/MSL results**: download the dataset, verify this assumption visually
  or against the dataset's own documentation, and adjust the `end + 1` slice
  in `load_nasa` if it's exclusive instead.

## Deliberate scope cuts (with reasoning)

- **No `Detector` base class with a generic `reset()`/`update()` streaming
  API.** The original spec (`AGENTS.md` Phase 0) called for this in every
  baseline. Built instead: `StreamingScorer` (`streaming/scorer.py`) achieves
  causal, per-timestep scoring via a ring buffer that re-scores the full
  window on each push, for every detector — proven equal to batch scoring
  by direct test (`test_streaming_scorer.py`). The one exception is EWMA,
  which genuinely needs recurrent state (its score depends on *all* history,
  not a fixed window) and has its own `reset_stream()`/`update_stream()`
  methods that `StreamingScorer` uses automatically when present. Net
  effect: correct, tested, but re-scores an entire window on every push
  rather than doing an O(1) incremental update for the deep models — see
  the README's Limitations section and the performance discussion below.

- **`experiment.py`/`report.py` don't persist per-run trained weights.**
  They fit, score, and record metrics in memory; nothing is saved to disk
  per run. `export.py` is a separate, deliberately explicit step: point it
  at a config, it refits the requested model and writes a full servable
  artifact (weights + scaler + threshold + drift reference). This means
  `export.py` retrains rather than reusing an experiment run's fitted
  model — an extra few seconds/minutes of compute in exchange for not
  needing every experiment run to serialize full model weights (which would
  make `reports/runs/` far larger, and most experiment runs are exploratory,
  not meant to be deployed).

- **No TranAD-style two-phase Transformer variant.** Listed in the original
  spec as a stretch goal, "only if explicitly requested" — never requested,
  not built.

- **No streaming SPOT** (an adaptive POT variant that updates its threshold
  using non-alarm points as they arrive). Also an explicit stretch item in
  the original spec; the static `PotThreshold` (fit once, at export time) is
  what's built and tested.

## Documented, tested limitations (not TODOs — known and accepted)

- **PSI's small-sample noise.** Verified directly during development: a
  ~30-50 point window drawn from the *same* distribution as the reference
  can show PSI in the 0.19-0.25 range (past the default 0.1 "warn"
  threshold) from sampling noise alone; a few-hundred-point window of the
  same data drops to ~0.01-0.02. `MIN_CURRENT_FOR_REPORT = 30` in
  `monitor/drift.py` is a crash guard, not a statistical-trustworthiness
  guarantee — treat any drift report built on a small `window` with
  appropriate skepticism, and prefer several hundred points per report for
  real decisions.

- **POT needs enough excesses.** `eval/pot.py`'s `MIN_EXCESSES_FOR_FIT = 10`
  logs a warning (not an error) when the chosen `level` quantile leaves too
  few points to fit a Generalized Pareto Distribution reliably. Observed
  directly in this repo's own `export.py` runs against small validation
  slices — the warning is doing its job, not a bug.

- **Streaming scorer performance.** Re-scores the full buffered window on
  every push rather than incrementally updating hidden state (except EWMA).
  Correct and tested; not the most efficient possible design for very high
  per-entity throughput. Real numbers: see the README's latency section
  (generated by `scripts/bench_latency.py`, both in-process and over real
  HTTP against a running server).

- **Docker build not verified in every environment.** Written to spec
  (`python:3.11-slim`, non-root user, healthcheck via Python stdlib rather
  than an extra `curl` install), but this development environment had no
  Docker daemon available to actually run `docker build` — the Dockerfile's
  correctness has not been confirmed by an actual build in every context it
  might run in. Confirm locally before relying on it.

## Design choices worth knowing (not limitations, just decisions)

- **`experiment.py` config entries support an optional `label` field**,
  distinct from `name`, so the same underlying model (e.g. `lstm_ae`) can
  appear multiple times in one config's results under different labels —
  this is what makes the 48-setting ablation sweep
  (`configs/ablation.yaml`) work without ablation-specific results-table
  code: each setting's `window`/`hidden`/`score_mode` combination becomes
  its own row via its `label`, and the existing `seed_stats_table`
  aggregation (renamed `ablation_table` for this use) already groups by
  exactly that.
- **`GET /drift/{entity_id}` never creates a new entity as a side effect.**
  A read endpoint that silently mutates state (consuming an entity-cap slot
  for an entity that never pushed anything) would be a surprising, hard-to-
  debug API design; `AppState.get_drift_monitor` explicitly does not call
  the entity-creating path that `get_scorer` uses.
